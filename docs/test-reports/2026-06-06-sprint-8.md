## Bug Found During Testing

**File:** `src/validation/mirror_node.py` — `check_memo_replayed()`

**Symptom:** Unit test 5 (`test_current_tx_skipped`) failed. The current transaction was NOT being correctly identified as the same transaction to skip, meaning the system would falsely flag every legitimate receipt as a replay (false positive).

**Root cause:** The comparison used `tx_id_raw.replace("@", "-").replace(".", "-", 2)` against `normalized_current`. The Mirror Node returns `transaction_id` in format `0.0.X-sec-nano` (dots preserved in account part). `_normalize_tx_id` also produces `0.0.X-sec-nano`. Applying `replace(".", "-", 2)` to the Mirror Node output converted `0.0.X` → `0-0-X`, breaking the equality.

**Fix:** Direct `==` comparison: `tx_id_raw == normalized_current`. Both sides are already in the same canonical format.

**Impact if not caught:** Every valid payment receipt would have been rejected with `uuid_replayed_on_chain` (false positive). Full payment system outage under S7.5.
